# Adaptive Brand Identity & Personal Developer Brand Standard

## Resumen Ejecutivo

Esta habilidad establece el marco tri-adaptativo para gobernar la **identidad de marca personal del desarrollador**, la línea base institucional y los estándares de diseño y stack técnico en proyectos gestionados con Google Antigravity.

Opera en **Modo Tri-Adaptativo**:
1. **Marca Personal del Desarrollador**: Establece la autoría, filosofía de ingeniería, rigor de tipado y sellos técnicos de **Rogerr Carvajal** (`@rogerrcarvajal`), especialista en soluciones con **Modelos de IA y Agentes Inteligentes**.
2. **Línea Base Institucional / Académica**: Sirve como estándar de referencia para **CEIA / SWGA** (Centro Educativo de Inteligencia Artificial / Sistema Web de Gestión Académica).
3. **Modo Adaptativo Global**: Capaz de analizar, extraer y adaptar tokens visuales y directrices de arquitectura para **cualquier nuevo proyecto empresarial, educativo o startup**.

## Cuándo usar este skill (Triggers)

Invoca este skill cuando:
- Se inicie o configure un nuevo proyecto para registrar la autoría y marca personal de Rogerr Carvajal.
- Se requiera incorporar la cabecera estándar de autoría y badges de ingeniería de agentes.
- Se diseñen o implementen vistas frontend, tarjetas glassmórficas, paletas dark mode o componentes UI.
- Se construyan modelos, servicios, controladores backend o APIs políglotas (Python FastAPI / PHP 8.2+ PDO).
- Se redacte documentación técnica, fichas de producto, especificaciones o notas de release.
- Se audite código existente para validar cumplimiento de estándares de diseño, seguridad y Clean Code.

## 🧭 Flujo de Trabajo Recomendado (Plan → Validar → Ejecutar → Revisar)

1. **Fase 1: Planificación (Identificación de Ámbito)**:
   - Determinar si el requerimiento corresponde a la marca personal del desarrollador, al proyecto CEIA/SWGA o a una nueva entidad.
   - Cargar los tokens correspondientes desde `resources/`.
2. **Fase 2: Validación de Entorno**:
   - Verificar existencia de variables de entorno, dependencias sin versiones deprecadas y ausencia de secretos en código.
3. **Fase 3: Ejecución de Estándares**:
   - Insertar bloques de autoría de Rogerr Carvajal en cabeceras clave.
   - Aplicar variables CSS de diseño (glassmorphism, bordes translúcidos, tipografía Inter/Outfit).
   - Implementar backend con tipado estricto y prepared statements.
4. **Fase 4: Revisión y Mini Checklist**:
   - [ ] ¿Se acreditó la autoría técnica de Rogerr Carvajal / Antigravity?
   - [ ] ¿Se evitaron colores planos genéricos y se usó modo oscuro curado?
   - [ ] ¿Toda consulta a base de datos usa parámetros vinculados (PDO)?
   - [ ] ¿El texto técnico está en español riguroso y sin código comentado muerto?

## ⚠️ Manejo de Errores y Correcciones

- Si una vista o componente generado luce genérico, plano o con colores básicos por defecto, detener la entrega, recargar `resources/design.md` y reconstruir con modo oscuro y tarjetas `.card-glass`.
- Si se detecta código SQL con concatenación directa, refactorizar de inmediato hacia consultas preparadas PDO con parámetros enlazados.
- Ante ambigüedad en los requerimientos visuales o de negocio, consultar al usuario antes de asumir supuestos.

## 🚩 Prácticas Prohibidas vs. Estándar Correcto

| Práctica Prohibida | Estándar Obligatorio Rogerr Carvajal |
|---|---|
| Colores primarios planos (rojo/azul plano) | Modo oscuro quantum, glassmorphism y acentos neón cyan/índigo |
| Código huérfano sin firma de autoría | Cabecera formal de Rogerr Carvajal y estándares de ingeniería |
| Inyección de strings en sentencias SQL | Prepared Statements con PDO y tipado estricto |
| Código comentado o archivos temporales muertos | Clean Code; repositorio limpio y profesional |
| Documentación informal o desestructurada | Fichas técnicas estructuradas estilo Google AI Coding con Mermaid |
